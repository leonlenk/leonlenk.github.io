# Links and notes

Links use ordinary underlined text, without hover previews.

Write footnotes using named Markdown references:

```md
Here is a thought worth expanding.[^detail]

[^detail]: Extra context, with an optional [source](https://example.com).

    A second paragraph can be indented by four spaces.
```

Notes sit in the right margin when there is enough room, aligned to their first
reference and spaced to avoid overlap. Smaller windows and pages without
JavaScript show endnotes. Each note includes a return link; repeated references
share one note. Note numbers and links are generated by Markdown.

## Image grids

Wrap multiple figures in `<div class="image-grid">` to tile images. This uses
a masonry-style layout with up to two columns, stacking on small screens.
Shorter images leave room for the next tile below them instead of leaving an
empty grid row. Reading order runs down the first column, then the second.
Images keep their original proportions and are not cropped. Each figure can
have its own caption; omit `<figcaption>` if it is not needed.

For example, in `src/content/posts/art/learning_how_to_draw.md`:

```md
<div class="image-grid">

<figure>

![An early drawing of Asa](./learning_how_to_draw/bad_asa.jpg)

<figcaption>My first attempt.</figcaption>
</figure>

<figure>

![An improved drawing of Asa](./learning_how_to_draw/asa.jpg)

<figcaption>After some help from a friend.</figcaption>
</figure>

</div>
```

Keep the blank lines shown above so Markdown images render inside the HTML.
Add more `<figure>` blocks inside the same div to add more tiles.
For links in a caption, use HTML, for example
`<figcaption>Reference by <a href="https://example.com">the artist</a>.</figcaption>`.

The About page’s webring uses the original 88×31 badges hosted by each site,
recovered from `main` (`02952af`). Keep their image URLs and native dimensions
when editing the links; the PepperSalt GIF retains its animation.
